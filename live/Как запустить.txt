Перрон-15 · Сайт смены

На ноутбуке
1. Запустите «Запустить.cmd» в папке сайта. Требуется Node.js 24.
2. Откройте http://127.0.0.1:8175. Оставьте окно сервера открытым.
3. Выберите «Диспетчер» и введите код из строки «Диспетчер» в окне сервера.
4. Для проверки двух ролей на одном компьютере откройте приватное окно браузера, выберите «Инженер» и введите один из инженерных кодов.

На Android по USB (для полной проверки на месте)
Подключите свой телефон к ноутбуку. Если используете Android Platform Tools и разрешили отладку по USB на этом телефоне, выполните на ноутбуке:
adb reverse tcp:8175 tcp:8175
Откройте http://localhost:8175 в Chrome на телефоне, войдите как инженер и нажмите «Включить GPS». Разрешите доступ к местоположению. Держите страницу открытой во время показа. После проверки отключите передачу и USB-отладку. Чтобы убрать перенаправление, выполните adb reverse --remove tcp:8175.

Для доступа с телефона по Wi-Fi требуется HTTPS с сертификатом, которому доверяет телефон. Сервер поддерживает переменные TLS_CERT и TLS_KEY для путей к PEM-сертификату и ключу, HOST для адреса прослушивания, PORT для порта. По умолчанию сайт слушает только этот компьютер.

Облачная смена
https://perron-15-live.onrender.com/ открывается на телефоне и ноутбуке. В Render откройте сервис perron-15-live и раздел Environment. Значения DISPATCH_CODE, ENGINEER_ONE_CODE, ENGINEER_TWO_CODE служат кодами для этих ролей, пока владелец их не изменит. Коды из окна локального сервера относятся только к локальной смене. Если переменные не заданы, локальный сервер при запуске создаёт новые коды. Повторный запуск при занятом порте сообщает об уже работающей копии.

Порядок работы
Диспетчер регистрирует зону, тип ВС, борт, дефект и приоритет. Доступны свободное описание с главой ATA, склад, входящее замечание и время прибытия ВС по расписанию. Инженер входит со своего телефона, включает GPS и разрешает доступ к местоположению. Держите страницу открытой. Вне территории ВДНХ телефон передаёт реальное положение, а поиск маршрута сообщает, что путь недоступен.
Для машины диспетчер выбирает «GPS телефона в машине» и передаёт полученную ссылку водителю. Официальный симулятор https://itsim.geolaba.net/ может постоянно отправлять координаты напрямую на https://perron-15-live.onrender.com/api/v1/track. Выключите «Через локальный CORS-прокси». Другим источникам нужен ключ либо временный приём без ключа. Обе роли и имитатор работают с одной сменой.
Подбор учитывает ATA, тип ВС при настроенном ограничении, текущий этап работы, наличие пригодной позиции и время по допустимым дорогам. После регистрации система автоматически предлагает вызов кандидату. При отказе или после 60 секунд без ответа система пересчитывает очередь. Для ручного выбора первого исполнителя поставьте галочку при регистрации. Инженер принимает вызов, следует по карте, после входа в зону начинает и завершает работу либо отмечает ожидание запчасти. При необходимости принимает решение AOG или MEL. Начатую работу возвращает только старший смены с подтверждением и причиной. Основной код диспетчера принадлежит старшему. Для обычного диспетчера и сотрудника MCC он выдаёт отдельные коды в «Управлении сменой». Оба входят через «Диспетчер». Сотрудник MCC записывает сообщение и передаёт проверенное замечание диспетчеру.
Кнопки «Показатели смены» и «Скачать журнал CSV» находятся внизу кабинета диспетчера. Хранение на компьютере — файл .perron-15/shift.sqlite в домашней папке пользователя. Путь задаёт переменная STATE_DB. На бесплатном Render хранение на локальном диске временное. До замены экземпляра скачайте нужный журнал. Для сохранения всей смены между развёртываниями нужен постоянный том, доступный серверу, с путём STATE_DB на этом томе.
Автотесты запускаются командой node --test в папке сайта. Проверки используют отдельную временную базу.

Выписка ATLB. В «Управлении сменой» выберите «Загрузить выписку ATLB». Образец для учебной смены (замените данными борта):
[{"ref":"ATLB-DEMO-1","tail":"TEST-01","ata":34,"description":"Отказ навигации","mel":"C","until":"2026-12-10T09:00:00Z"}]
Историю по борту и главе ATA видит инженер. Решение и срок вводит сам инженер.
